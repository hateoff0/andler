# andler-net

Network configuration for virtual machine instances. Provides bridge and NAT network setup for QEMU virtual machines.

## Current State

Implements all three network modes for host-side configuration: NAT (slirp/passt), bridge (a host bridge plus a per-instance tap), and isolated. **Isolated gives the guest its own unprivileged user + network namespace**: `setup_isolated` returns the tap name and the argv prefix that launches the guest's QEMU inside that namespace, where the tap is the only interface and no route to a host network exists — QMP/QGA stay reachable because they are UNIX sockets. Setup validates the result before returning (exactly `lo` plus the tap, no IPv4 route) and refuses with an actionable reason when the host cannot provide a namespace; teardown is idempotent, and the daemon derives the same tap name on a restart so an adopted guest can still be stopped.

## Features

- **Bridge mode**: Attach VM to an existing Linux bridge on the host. Implemented.
- **Isolated mode**: A fully isolated network with no external connectivity. **Not implemented** — the config type exists (`NetworkMode::Isolated`), the QEMU cmdline even has a slot for it, but the host-side setup errors out.
- **NAT mode**: Provide NAT-based network access with configurable backend (Slirp or Passt). Implemented.

## How It Works

The `DefaultNetworkService` uses the `ip` command (from iproute2) to configure network interfaces:

- **Bridge setup**: Creates a TAP interface, adds it to the specified bridge, and brings both up.
- **Bridge teardown**: Removes the TAP interface from the bridge. The bridge itself is intentionally left UP — it may be shared with other VMs or host network. Only the TAP interface is removed.

## QEMU Integration

`andler-qemu` integrates the network service:

- Before spawning QEMU, the appropriate network setup is performed (bridge only — isolated setup errors).
- After stopping QEMU, the network teardown is performed.

The QEMU command-line arguments are generated by `cmdline::network_args`:

- Bridge mode: `-netdev tap,id=net0,ifname=tap{ID},bridge={bridge},script=no,downscript=no -device virtio-net-pci,netdev=net0`
- NAT mode (Slirp): `-netdev user,id=net0 -device virtio-net-pci,netdev=net0`
- NAT mode (Passt): `-netdev passt,id=net0 -device virtio-net-pci,netdev=net0`

## Dependencies

- `andler-core` for `NetworkConfig` and `NetworkMode` types.
- `tokio` for async command execution.
- `thiserror` for error handling.
