# 0002 — Сборка и тесты в Docker, раздельные таргеты unit/integration

**Статус:** принято

## Контекст

Сборка и тесты ANDLER должны быть воспроизводимы независимо от версии Rust
и системных библиотек на машине конкретного разработчика. Часть тестов
(`andler-qemu`, в перспективе `andler-daemon`) требует реального процесса
`qemu-system-x86_64` и доступа к `/dev/kvm`; `andler-core` — чистый домен,
без такой зависимости (см. README `andler-core`).

## Решение

Один multi-stage `docker/Dockerfile.dev` с раздельными таргетами:

- `unit-test` — `cargo test --workspace` без `--device=/dev/kvm`. Безопасно
  гонять на любом CI-раннере, в том числе без виртуализации.
- `integration-test` — устанавливает `qemu-system-x86`/`qemu-utils`, гоняет
  тесты, явно помеченные `#[ignore]` из-за зависимости от KVM
  (`cargo test -- --ignored`). Требует `--device=/dev/kvm` при запуске
  контейнера.
- `daemon` — минимальный runtime-образ `andlerd`, только для разработки
  (docker-compose), не для продуктового деплоя.

## Альтернативы, которые не выбраны

- **Один таргет для всех тестов.** Отклонено: либо КВМ-зависимость
  просачивается в обычный CI-прогон на каждый PR (где не у каждого раннера
  есть `/dev/kvm`), либо интеграционные тесты молча игнорируются без явного
  отдельного шага.
- **Тестирование без Docker, прямо на хосте разработчика.** Отклонено как
  единственный способ: даёт быструю локальную итерацию, но не даёт
  воспроизводимости версий Rust/системных либ между разработчиками и CI.
  Прямой запуск `cargo test` на хосте остаётся допустимым для быстрой
  локальной разработки — Docker не заменяет это, а добавляет
  воспроизводимый прогон поверх.

## Последствия

- CI получает два job'а вместо одного, в соответствии с §7
  `CORE_ARCHITECTURE_PLAN.md`: `unit-test` на каждый PR, `integration-test`
  на merge в основную ветку (раннер для второго job'а должен поддерживать
  nested virtualization).
- Любой новый тест, обращающийся к реальному QEMU-процессу, обязан получить
  `#[ignore]` с комментарием-причиной — иначе он либо упадёт в
  `unit-test`-таргете, либо тихо не будет учитываться в покрытии
  интеграционных сценариев.
