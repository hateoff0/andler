# ANDLER — концепция продукта
### Open-source платформа-менеджер виртуальных машин и Android-сред для Linux с GPU-ускорением

> **Статус документа:** продуктовая концепция / видение.
> Документ описывает **что** продукт должен делать и какой опыт давать пользователю — весь функционал максимально подробно, без привязки к конкретным библиотекам, языкам программирования и порядку разработки. Это материал-основа для последующего технического плана.
> **ANDLER** — рабочее название. Расшифровка: *Android Linux Emulator & Runtime*, а также неформально — *тот, кто управляет ("handle") Android и Linux-средами*.

---

## 0. Важное уточнение позиционирования

ANDLER — это **не эмулятор Android**, а **универсальный менеджер виртуальных машин** с упором на удобство, GPU-ускорение и Android как один из сценариев использования. Это принципиально:

- Пользователь может создавать **обычные виртуальные машины** (любой Linux, в перспективе — и другие гостевые ОС) — как полноценная замена VirtualBox/virt-manager/GNOME Boxes, но с готовым из коробки графическим ускорением.
- Пользователь может создавать **Android-инстансы** — как замена BlueStacks/LDPlayer/Genymotion.
- Оба типа сред управляются **одним и тем же менеджером**, одной логикой ресурсов, дисков, сети, рендеринга — пользователь учится один раз.
- Продукт работает **на любом GPU** — NVIDIA, AMD, Intel — а не является "костылём только для NVIDIA". Поддержка систем без GPU вообще (program rendering / CPU) — полноценный официальный режим, а не аварийный.

## 1. Резюме продукта

ANDLER — open-source приложение для Linux, позволяющее одним кликом создавать, настраивать и запускать изолированные **виртуальные среды** двух основных типов:

1. **VM-окружения (общего назначения)** — любой Linux-дистрибутив из ISO/образа пользователя, с GPU-ускорением "из коробки", без ручной настройки виртуализации.
2. **Android-окружения** — полноценный Android с аппаратным ускорением графики, рассчитанный на игры и приложения, работающий одинаково хорошо на NVIDIA, AMD и Intel.

Каждая среда — самостоятельный управляемый **инстанс**, который можно клонировать, ставить на паузу, переносить, удалять, сжимать по размеру диска и настраивать индивидуально: от количества ядер CPU и объёма ОЗУ до способа рендеринга графики, движка вывода изображения и трансляторов архитектур.

Главная идея: **дать пользователям Linux то, что BlueStacks и VirtualBox дают по отдельности — но в одном open-source инструменте, с полным контролем над начинкой, без привязки к одному вендору GPU и без рекламы/телеметрии.**

## 2. Проблема и мотивация

- Штатный **Waydroid** не работает с проприетарными драйверами NVIDIA (нет поддержки GBM/EGL), что исключает значительную долю Linux-десктопов.
- Рабочий обходной путь — поднять микро-VM с virtio-gpu/Venus и запускать Waydroid внутри — работает, но требует ручной сборки ядра, настройки QEMU, работы с диском вручную. Это недоступно обычному пользователю.
- Коммерческие аналоги (BlueStacks, LDPlayer, GameLoop) существуют только под Windows, закрыты, перегружены рекламой/телеметрией, не дают гибкости в выборе способа рендеринга и не работают одинаково на всех GPU.
- Существующие VM-менеджеры для Linux (VirtualBox, virt-manager, GNOME Boxes) не заточены под игровой 3D-сценарий "из коробки" — GPU-ускорение там настраивается вручную и часто плохо документировано.
- Нет ни одного инструмента, который закрывал бы **и** «Android как у BlueStacks», **и** «быстрая VM под любой Linux с ускорением графики», **и** работал бы одинаково хорошо на любом железе (включая системы без дискретной GPU).

ANDLER закрывает все эти ниши одним продуктом.

## 3. Видение и принципы продукта

| Принцип | Что это значит на практике |
|---|---|
| **Vendor-agnostic с самого начала** | Работает одинаково хорошо на NVIDIA, AMD, Intel и системах без GPU — за счёт выбора способа рендеринга, а не надежды на один путь. |
| **Это менеджер VM, а не "эмулятор с настройками"** | Пользователь может создать произвольную виртуальную машину под любые задачи, а не только Android. |
| **Прозрачность** | Пользователь в любой момент видит и понимает, какие ресурсы потребляет каждый инстанс и почему. |
| **Минимальный инпут-лаг как метрика качества** | Ввод (мышь, клавиатура, геймпад, датчики) — приоритетная зона оптимизации. |
| **Разумные настройки по умолчанию + полный доступ "под капотом"** | Новичок жмёт «Создать» и получает рабочий профиль; опытный пользователь задаёт любой параметр вручную. |
| **Открытость** | Открытый исходный код, открытый формат конфигов и образов, без телеметрии и рекламы. |

## 4. Целевая аудитория и сценарии использования

- **Геймеры на Linux** — мобильные игры (шутеры, MOBA, гонки) на полноценном экране ПК с любым GPU.
- **Разработчики и QA-инженеры** — несколько чистых Android-сред одновременно для тестирования на разных "виртуальных устройствах".
- **Power-пользователи Linux** — быстрая VM с GPU-ускорением для любых задач (тестирование дистрибутивов, изолированное рабочее окружение) без танцев с libvirt.
- **Стримеры/контент-мейкеры** — чистый видео/аудио вывод инстанса в OBS без записи всего экрана.
- **Энтузиасты приватности** — изолированная одноразовая среда для запуска недоверенного APK/ISO.
- **Пользователи без выделенной видеокарты** — полноценная работа в режиме программного рендеринга (CPU) как официальный, а не "аварийный" режим.

## 5. Режимы и типы создаваемых сред

ANDLER — единый менеджер, в котором при создании новой среды пользователь выбирает **тип**:

### 5.1 Произвольная виртуальная машина (VM общего назначения)
Подключение любого ISO/образа диска любого Linux (в перспективе — и других ОС). ANDLER поднимает VM с GPU-ускорением, выбранным способом вывода изображения, сетью и диском — без слоя Android, как готовый к работе гипервизор "из коробки".

### 5.2 Android-инстанс через Waydroid-в-VM (основной режим для максимальной совместимости, в т.ч. NVIDIA)
Внутри лёгкой гостевой Linux-системы автоматически разворачивается и настраивается Waydroid. Пользователь видит просто «Android-инстанс»; вся «обвязка» с микро-Linux скрыта по умолчанию, но доступна продвинутым пользователям в "расширенном режиме".

### 5.3 Android-инстанс через прямой Android-x86/ReDroid-подобный образ
Для систем, где штатная контейнеризация работает нормально без вложенной VM — более лёгкий путь напрямую. Выбор между VM-режимом и контейнерным режимом решается автоматически профилем совместимости, но доступен и ручной выбор.

### 5.4 Клон/шаблон
Новый инстанс как полная или лёгкая (linked clone / copy-on-write) копия существующего — для тестовых ферм и быстрого разворачивания одинаковых сред.

### 5.5 Авто-режим (рекомендуется новичкам)
При создании ANDLER сам определяет видеокарту, драйвер и тип контента и предлагает оптимальный профиль рендеринга и ресурсов одним кликом, с возможностью открыть ручную настройку.

## 6. Графика и рендеринг (с учётом универсальности GPU)

Ключевой принцип: **рендеринг и вывод изображения — это два разных, независимо настраиваемых слоя.**

### 6.1 Способы 3D/2D-рендеринга внутри гостя (Rendering Backend)
- **VirtIO-GPU + Venus (Vulkan-проксирование)** — максимальная производительность, проброс Vulkan из гостя на GPU хоста; основной режим для требовательных игр.
- **VirtIO-GPU (стандартный, vendor-agnostic)** — универсальный виртуальный 3D-рендер, хорошо работающий на широком круге GPU без специфичных требований к драйверу.
- **VirGL (OpenGL ES проксирование)** — альтернатива для гостевых систем/приложений, рассчитанных на OpenGL ES, а не Vulkan.
- **Программный рендеринг на CPU (llvmpipe / SwiftShader)** — официальный, полноценно поддерживаемый режим: для систем без GPU, для headless-серверов, для диагностики и лёгких приложений без 3D-нагрузки.
- **Полный проброс GPU (passthrough)** — опциональный продвинутый режим для систем с несколькими видеокартами: инстанс получает физическую GPU целиком.
- **Авто-определение оптимального варианта** при создании — с понятным объяснением "почему рекомендован этот вариант".
- **Выбор конкретной GPU** на системах с несколькими видеокартами — какому инстансу какая карта.

### 6.2 Движки вывода изображения на экран хоста (Display Engine) — отдельный от рендеринга слой
Пользователь выбирает, **как именно** окно ANDLER взаимодействует с рабочим столом, независимо от выбранного способа 3D-рендеринга:
- **Встроенное окно (Native Window)** — классический оконный режим (SPICE/GTK/SDL-подобный), интерфейс и кнопки управления в одной рамке.
- **Бесшовный режим (Seamless)** — каждое Android-приложение открывается отдельным нативным окном Linux на рабочем столе хоста, минуя отрисовку всего "рабочего стола" Android — как будто это обычная программа.
- **Стриминговый движок (низкая задержка, по сети)** — вывод картинки по сетевому протоколу с минимальной задержкой; полезно, когда ANDLER крутится на домашнем сервере/другом ПК без монитора, а управление идёт с ноутбука/телефона в той же сети.
- **Headless без вывода** — без какой-либо отрисовки на экран, для серверных и фоновых сценариев.
- Возможность **на ходу переключать движок вывода** для одного и того же запущенного инстанса без его перезапуска (где это технически осмысленно).

### 6.3 Прочие настройки графики
- Разрешение экрана: пресеты "телефон/планшет/десктоп" + произвольное.
- DPI/плотность пикселей для Android-инстансов.
- Несколько сохранённых профилей дисплея на один инстанс (например, "телефон вертикально" / "планшет горизонтально"), переключаемых на ходу.
- Ограничитель FPS (30/60/90/120/безлимит), поддержка адаптивной синхронизации (VRR/G-Sync/FreeSync).
- Динамическое масштабирование рендера (внутреннее разрешение ниже окна + апскейл) для экономии ресурсов GPU.
- Режимы окна: оконный, безрамочный, полноэкранный, поддержка нескольких мониторов.
- HUD быстрых настроек прямо в сессии — смена рендеринга/движка вывода/FPS-лимита без выхода из полноэкранного режима.

## 7. Процессор, память и ресурсы

- Выделение ядер CPU — конкретное число/диапазон, привязка к физическим ядрам (affinity), приоритет процесса.
- Выделение ОЗУ — фиксированный объём с рекомендациями "минимум/комфорт/максимум" под тип гостя.
- **Memory Ballooning** — динамический возврат свободной памяти хосту, если инстанс сейчас использует меньше, чем выделено (через guest-agent), без необходимости перезапуска.
- **ZRAM/сжатый своп внутри гостя** — автоматическая настройка сжатия оперативной памяти в гостевой Android-системе, чтобы комфортно работать даже при небольшом выделенном объёме ОЗУ.
- **KSM (Kernel Samepage Merging)** на хосте — дедупликация одинаковых страниц памяти между несколькими похожими инстансами, существенная экономия ОЗУ при множественных копиях.
- Приоритет ресурсов между инстансами при одновременном запуске нескольких сред и нехватке CPU/GPU.
- Живой монитор ресурсов (CPU/RAM/диск/сеть/GPU) в реальном времени по каждому инстансу и сводно по системе.

## 8. Хранилище и диски

- Гибкий размер диска — указание максимума с возможностью изменения позже.
- Тонкое/толстое выделение ("расти по мере использования" vs "занять всё сразу").
- Автоматическое сжатие после выключения (компактизация образа, чтобы реальный занятый объём соответствовал фактическим данным).
- Периодическая компактизация по расписанию для долгоработающих инстансов.
- TRIM/discard внутри гостя при выключении для освобождения места на хосте.
- Произвольное расположение файлов отдельно для: образов дисков, конфигов, кэша, логов, снэпшотов (например, диски на NVMe, архивы на HDD).
- Несколько виртуальных дисков на инстанс: системный + диск данных + виртуальная SD-карта (для Android).
- **Связанные/лёгкие клоны (linked clones, copy-on-write)** — несколько инстансов на общем неизменяемом базовом образе, хранят только свои отличия.
- **Мгновенный сброс к заводским настройкам (OverlayFS Factory Reset)** — диск работает слоями; "Сброс" просто удаляет верхний слой пользовательских данных, возвращая чистый Android/Linux за секунду без переустановки образа.
- Шифрование диска (опционально) для приватных/чувствительных сред.
- Бэкап и восстановление инстанса целиком, ручное и по расписанию.

## 9. Сеть

- Режим сети на каждый инстанс: **NAT** (по умолчанию), **Bridge** (свой IP в локальной сети), **изолированный режим без сети**.
- Проброс портов — таблица правил "порт хоста → порт инстанса".
- Per-instance VPN/прокси — трафик конкретного инстанса через отдельный SOCKS5/HTTP-прокси или WireGuard-конфиг, не затрагивая остальную систему.
- Собственный MAC-адрес/DNS на инстанс — для изоляции сетевого отпечатка.
- Ограничение скорости (QoS) на инстанс, чтобы фоновые среды не мешали основной работе.

## 10. Ввод, управление и гейминг

- **Редактор маппинга клавиш на касания (keymapping)** — визуальный оверлей: клавиши клавиатуры и движения мыши → тапы/свайпы/удержания/мультитач-зоны на экране Android.
- **Захват мыши ("mouse lock")** по горячей клавише — обзор на 360° как в ПК-играх, с индикацией "захвачена/свободна".
- **Поддержка геймпада** — проброс физического контроллера "как есть" либо программная эмуляция геймпада из клавиатурных команд.
- **Эмуляция сенсоров через клавиатуру/геймпад** — акселерометр/гироскоп (например, наклон для гонок).
- **Гироскоп через приложение-компаньон на смартфоне** — отдельное лёгкое приложение, которое по Wi-Fi передаёт данные реального гироскопа телефона в ANDLER: можно "рулить" наклоном настоящего телефона, пока игра выполняется на ПК.
- **Мультитач через трекпад ноутбука** — жесты двумя/тремя пальцами (зум, вращение) транслируются в мультитач-события внутри Android.
- **Макросы** — запись последовательности действий и воспроизведение по кнопке/горячей клавише.
- **Профили управления на игру/приложение** — сохранённые наборы маппинга, переключаемые автоматически и доступные для обмена между пользователями.
- **HUD быстрых настроек в сессии** (см. также п. 6.3).

## 11. Звук

- Выбор устройств ввода/вывода звука для каждого инстанса отдельно.
- Виртуальный микрофон — проброс реального микрофона хоста внутрь гостя.
- Индивидуальная громкость на инстанс и микширование с системным звуком.
- Режим низкой задержки звука vs режим максимальной совместимости.
- Автоматическое приглушение свёрнутых/фоновых инстансов.

## 12. Интеграция с хостом

- Двусторонний общий буфер обмена (текст между хостом и гостем в обе стороны).
- **Drag-and-drop**: `.apk` → автоустановка; файлы/изображения → папка загрузок гостя; для Linux-режима — в общую папку.
- **Общие папки** — директория хоста доступна внутри гостя с производительностью, близкой к нативной, без классических сетевых протоколов.
- Зеркалирование уведомлений Android в системный трей хоста.
- Глобальные горячие клавиши хоста: переключение между запущенными инстансами, скриншот, запись видео, переключение режима окна.
- Вынесение отдельного Android-приложения как самостоятельного ярлыка в меню приложений хоста (без открытия всего менеджера).

## 13. Производительность и многозадачность

- **Пауза/возобновление (freeze/resume)** — фоновые инстансы "замораживаются", почти не потребляют CPU, состояние сохраняется, мгновенное возобновление по клику.
- Дедупликация памяти между похожими инстансами (см. KSM, п. 7).
- **Синхронизация действий между инстансами ("мультиоконный ввод")** — действия в одном "ведущем" окне опционально зеркалируются в несколько других одновременно (параллельное QA-тестирование на нескольких виртуальных устройствах).
- Очередь автозапуска — какие инстансы стартуют при включении хоста или по расписанию.
- Уведомления о состоянии: нехватка места на диске, перегрузка CPU/RAM, сетевые проблемы конкретного инстанса.

- Переключатель root-доступа с понятным предупреждением о последствиях для безопасности.
- **Менеджер Magisk/KernelSU-модулей** — установка популярных root-модулей прямо из интерфейса, перетаскиванием `.zip` в окно настроек инстанса.
- Менеджер приложений — единый список установленных приложений по всем инстансам; пакетная установка/удаление/обновление сразу в нескольких выбранных.
- Резервное копирование данных конкретного приложения отдельно от всего диска.
- Магазин приложений — GAPPS
- Подмена данных устройства (модель "телефона", IMEI, Android ID, MAC) для тестов совместимости и обхода ограничений по FPS/настройкам.
- Локаль, часовой пояс, имитация GPS-координат — независимо на каждый инстанс.
- Менеджер разрешений приложений — централизованная панель с хоста.

- **"ANDLER Presets" — пресеты под конкретные игры**: по аналогии с готовыми патчами загружается набор настроек для конкретной популярной игры — оптимальный маппинг клавиш, нужный режим транслятора, при необходимости настройки скрытия признаков виртуализации/root от защитных систем игры, рекомендуемый профиль рендеринга.

## 16. Фоновый режим и удалённый доступ

- Headless-запуск — без открытого окна, минимум ресурсов на отображение, но с доступом при необходимости.
- Удалённый доступ к экрану работающего в фоне инстанса с другого устройства в сети.

- Серверные сценарии — несколько headless Android/Linux инстансов как фоновые "рабочие лошадки" для автоматизированных задач.

## 25. Пользовательские сценарии

**A — Геймер с любым GPU.** Устанавливает ANDLER, создаёт Android-инстанс; система сама определяет видеокарту (будь то NVIDIA, AMD или Intel) и выставляет оптимальный рендеринг. Настраивает keymapping и захват мыши для шутера, играет с минимальным откликом.

**B — QA-инженер.** Клонирует базовый инстанс пять раз лёгкими клонами, назначает каждому свой профиль экрана/локаль, пакетно устанавливает тестовую сборку drag-and-drop одного файла на все окна сразу.

**C — Тестирование незнакомого ISO.** Создаёт одноразовый изолированный Linux-инстанс без сети и общих папок, тестирует, после чего инстанс автоматически уничтожается.

**D — Стример.** Выводит видео/звук Android-инстанса как чистый источник в OBS, без интерфейса менеджера и без лагов захвата всего экрана.

**E — Домашний сервер.** Headless Android-инстанс с автозапуском, без ресурсов на отображение, доступный удалённо при необходимости.

**F — Гонки с настоящим телефоном в руках.** Подключает приложение-компаньон на смартфоне, рулит наклоном настоящего телефона в мобильной гонке, запущенной на мощном ПК.

**G — Обычная виртуалка для работы.** Поднимает произвольный Linux ISO как изолированное рабочее окружение с GPU-ускорением для 3D-приложений — не открывая для этого ни одного Android-инстанса, используя ANDLER просто как удобный гипервизор.

## 27. Принципы UX

- Ноль обязательных решений для новичка: "Создать → Запустить" работает без единого вопроса, на который новичок не знает ответа.

- Единый язык интерфейса для VM- и Android-режимов — пользователь учится один раз.

## 29. Глоссарий

- **Инстанс (instance)** — отдельная управляемая виртуальная Android- или Linux/VM-среда внутри ANDLER.
- **Venus** — способ передачи Vulkan-команд из гостевой системы на видеокарту хоста для аппаратного 3D-ускорения внутри VM.
- **VirtIO-GPU** — более универсальный, менее зависимый от вендора способ виртуализации графики.
- **VirGL** — проксирование OpenGL ES для гостевых систем/приложений на этом API.
- **Движок вывода изображения (Display Engine)** — способ доставки готовой картинки из VM на экран хоста: окно, бесшовный режим, стриминг или его отсутствие (headless); независим от способа рендеринга.
- **Headless-режим** — работа инстанса без отображения окна на экране.
- **Связанный клон (linked clone)** — копия инстанса, хранящая только отличия от общего базового образа.
- **OverlayFS Factory Reset** — мгновенный сброс инстанса к чистому состоянию за счёт удаления верхнего слоя файловой системы.
- **Транслятор архитектур** — слой, позволяющий ARM-приложениям работать на x86-процессоре хоста.
- **Дедупликация памяти (KSM)** — объединение одинаковых данных в ОЗУ между похожими инстансами для экономии памяти.
- **Memory Ballooning** — динамический возврат хосту памяти, не используемой гостем в данный момент.
- **ANDLER-Proton (пресет)** — готовый набор настроек (маппинг, транслятор, рендеринг) под конкретную популярную игру/приложение.
