# 0001 — Overlay-диск (backing_file) для Android-инстансов вместо снапшотов

**Статус:** принято

## Контекст

Android-инстанс (`InstanceKind::AndroidVm`) должен запускаться из готового
гостевого образа с предустановленным Waydroid (см. `GUEST_IMAGE_PLAN.md`),
поддерживать быстрый Factory Reset и дешёвое создание нескольких
независимых инстансов на одном базовом образе.

## Решение

Каждый Android-инстанс получает overlay-диск формата qcow2 с
`backing_file`, указывающим на общий read-only базовый образ
(`DiskConfig::overlay`, см. `crates/andler-core/src/config/disk.rs`).
Базовый образ никогда не модифицируется напрямую. Подробности жизненного
цикла — `CORE_ARCHITECTURE_PLAN.md`, §4.4.

## Последствия

- Factory Reset — это пересоздание overlay-файла с нуля (секунды), а не
  переустановка системы.
- Несколько Android-инстансов с одинаковым `AndroidProfile::cache_key()`
  делят один базовый образ на диске — линейная экономия места вместо
  N полных копий.
- Цена: backing-chain в qcow2 добавляет накладные расходы на чтение
  (разрешение через base при отсутствии данных в overlay) — не измерено
  количественно, но это известное и принятое поведение qcow2
  backing-файлов, а не специфичный для ANDLER риск.
- Альтернатива (полные клоны на каждый инстанс) была бы проще в реализации,
  но кратно дороже по месту на диске и медленнее при создании инстанса —
  отклонена.
